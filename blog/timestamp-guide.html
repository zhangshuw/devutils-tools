时间戳转换详解：Unix 时间戳、毫秒时间戳与各语言获取方法

发布于 2026年5月21日 · 阅读时间约8分钟

前后端对接时，时间戳是最容易出问题的地方之一。秒级还是毫秒级？13 位还是 10 位？时区怎么处理？本文帮你彻底搞懂时间戳。

什么是 Unix 时间戳？

Unix 时间戳是从 1970年1月1日 00:00:00 UTC 到指定时间所经过的秒数。也叫 Epoch time 或 POSIX time。

例如：

时间时间戳（秒）时间戳（毫秒）
1970-01-01 00:00:00 UTC00
2000-01-01 00:00:00 UTC946684800946684800000
2026-01-01 00:00:00 UTC17672256001767225600000

秒级 vs 毫秒级

最常见的坑就是搞混秒级和毫秒级：

  • 秒级（10 位）：Unix 原始定义，大多数后端语言默认
  • 毫秒级（13 位）：JavaScript 默认，Java 常用
语言/平台默认精度位数
JavaScript毫秒13 位
Python秒（float 含微秒）10 位

MySQL秒10 位

各语言获取当前时间戳

JavaScript

// 毫秒级
Date.now()                        // 1779354362058
new Date().getTime()               // 同上

// 秒级
Math.floor(Date.now() / 1000)      // 1779354362

Python

import time

# 秒级
int(time.time())                   # 1779354362

# 毫秒级
int(time.time() * 1000)            # 1779354362058

Java

// 毫秒级
System.currentTimeMillis()         // 1779354362058

// 秒级
System.currentTimeMillis() / 1000  // 1779354362

Go

import "time"

// 秒级
time.Now().Unix()                  // 1779354362

// 毫秒级
time.Now().UnixMilli()             // 1779354362058

MySQL

-- 秒级
SELECT UNIX_TIMESTAMP();           -- 1779354362

-- 毫秒级
SELECT UNIX_TIMESTAMP(NOW(3)) * 1000;

命令行

# macOS / Linux
date +%s                          # 秒级
date +%s%3N                       # 毫秒级

时间戳与日期互转

JavaScript

// 时间戳 → 日期
new Date(1779354362000).toISOString()  // "2026-05-21T08:26:02.000Z"

// 日期 → 时间戳
new Date("2026-05-21").getTime()       // 1779283200000

Python

from datetime import datetime

# 时间戳 → 日期
datetime.fromtimestamp(1779354362)  # datetime(2026, 5, 21, 16, 26, 2)

# 日期 → 时间戳
datetime(2026, 5, 21).timestamp()   # 1779283200.0

常见问题

时间戳为什么是 1970 年开始？

Unix 系统诞生于 1969-1970 年间，开发者选择 1970-01-01 作为起点（Unix Epoch），方便计算。这个约定延续至今。

2038 年问题是什么？

32 位有符号整数最大值是 2147483647，对应 2038-01-19 03:14:07 UTC。超过这个时间，32 位系统的 Unix 时间戳会溢出。现代 64 位系统不受影响。

时区对时间戳有影响吗？

没有。时间戳是基于 UTC 的绝对值，不受时区影响。但将时间戳转换为日期字符串时，需要考虑时区。同一个时间戳在北京显示为 16:00，在伦敦显示为 08:00。
