MD5、SHA-1、SHA-256 有什么区别？哈希算法选择指南

发布于 2026年5月21日 · 阅读时间约8分钟

开发中经常需要计算文件的哈希值——验证下载完整性、存储密码、生成唯一标识……但 MD5、SHA-1、SHA-256、SHA-512 这些算法有什么区别？应该选哪个？这篇文章给你讲清楚。

什么是哈希？

哈希（Hash）是一种单向函数：把任意长度的输入变成固定长度的输出。就像指纹一样——不同的人有不同的指纹，同一个人的指纹永远相同。

关键特性：

  • 确定性：相同输入永远产生相同输出
  • 不可逆：从哈希值无法推算原始数据
  • 雪崩效应：输入微小变化，输出完全不同
  • 抗碰撞：很难找到两个不同输入产生相同输出

常见哈希算法对比

算法输出长度安全性速度典型用途
MD5128 位（32 字符）❌ 已破解很快文件校验、缓存键
SHA-1160 位（40 字符）❌ 已破解快Git 提交哈希（历史遗留）
SHA-256256 位（64 字符）✅ 安全中等数字签名、区块链、密码存储
SHA-512512 位（128 字符）✅ 安全较慢高安全场景、大文件校验

MD5：已不安全但仍在用

MD5 是最古老的哈希算法之一，输出 32 个十六进制字符：

MD5("hello") = 5d41402abc4b2a76b9719d911017c592

MD5 的致命问题：

  • 2004 年被发现存在碰撞攻击——可以人为构造两个不同文件具有相同 MD5
  • 彩虹表攻击可在秒级破解常见密码的 MD5

不要用 MD5 存密码！MD5 只适合非安全场景：文件去重、缓存键、调试日志指纹。

SHA-1：正在被淘汰

SHA-1 输出 40 个十六进制字符，比 MD5 安全但已在 2017 年被攻破：

SHA1("hello") = aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d

SHA-1 的使用场景正在快速减少：

  • Git 正在迁移到 SHA-256
  • SSL 证书已停止使用 SHA-1 签名
  • Chrome 等浏览器会标记 SHA-1 证书为不安全

SHA-256：当前推荐

SHA-256 是 SHA-2 家族中最常用的算法，输出 64 个十六进制字符：

SHA256("hello") = 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

你应该在以下场景优先选择 SHA-256：

  • 文件完整性校验（下载验证）
  • 数字签名
  • 密码存储（配合 salt 和迭代次数）
  • API 签名验证
  • 区块链数据哈希

密码存储的正确方式

直接用 SHA-256 存密码仍然不够安全（彩虹表攻击）。正确做法是：

  1. 生成随机盐值（salt），每个用户不同
  2. 使用 bcrypt、scrypt 或 Argon2 代替 SHA-256
  3. 这些算法内置盐值和迭代，专门设计用于密码存储
// Node.js 密码存储示例（bcrypt）
const bcrypt = require('bcrypt');
const hash = await bcrypt.hash(password, 10);  // 10 = cost factor
const match = await bcrypt.compare(inputPassword, hash);

各语言计算哈希示例

JavaScript（浏览器）

const text = "hello";
const buffer = new TextEncoder().encode(text);
const hash = await crypto.subtle.digest('SHA-256', buffer);
const hex = Array.from(new Uint8Array(hash))
  .map(b => b.toString(16).padStart(2, '0'))
  .join('');
console.log(hex);

Python

import hashlib
text = "hello"
sha256 = hashlib.sha256(text.encode()).hexdigest()
print(sha256)

命令行

# macOS / Linux
echo -n "hello" | shasum -a 256

# 使用 OpenSSL
echo -n "hello" | openssl dgst -sha256
